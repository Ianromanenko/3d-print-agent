# SETUP — установка агента на свой Mac

Пошаговая инструкция для того, кто получил этот репозиторий и хочет запустить агента у себя.
Рассчитана на связку **Bambu Lab A1 + Bambu PETG HF** — под неё заточены профили слайсера.
Если у тебя другой принтер или пластик — см. раздел [«Другое железо»](#другое-железо) в конце.

---

## 0. Что ты получаешь

Агент, которому ты описываешь деталь словами («напечатай 6 шестерён Ø20 мм, module 1,
толщина 5, отверстие 5»), а он: уточняет, что понял → генерирует настоящую CAD-модель
(отдельный STL на каждый объект) → проверяет её на печатаемость → рендерит и **смотрит на неё
своим зрением**, сверяя с твоим запросом → нарезает с профилем PETG HF → отдаёт `.gcode.3mf`.

Важно понимать разделение:

| Часть | Кто исполняет | Чем является |
|---|---|---|
| Понимание запроса, уточнения, зрительный само-чек | **Claude Code-сессия** | «мозг», промпт в `agent/BRAIN.md` |
| Генерация CAD, ворота печатаемости, рендер, слайсинг, связь с принтером | **Python-пакет `agent/`** | «руки», детерминированный CLI |

Из этого следует главное требование: **без Claude Code работает только «руки»** — то есть
детерминированные команды вроде `python -m agent.pipeline gear`. Диалог «опиши деталь словами»
требует подписки на Claude Code.

## 1. Требования

| Что | Зачем | Проверка / установка |
|---|---|---|
| **macOS** | агент писался и тестировался на Mac (Apple Silicon) | — |
| **Claude Code** | «мозг» агента — сессия Claude в этой папке | https://claude.com/claude-code |
| **uv** | менеджер Python-окружений | `brew install uv` |
| **Python 3.12** | ставит сам `uv` — **не 3.14!** | см. прим. ниже |
| **OrcaSlicer** | headless-слайсинг | `brew install --cask orcaslicer` |
| **Bambu Lab A1** | собственно принтер, в одной Wi-Fi-сети с Mac (**только 2.4 ГГц**) | — |
| **Bambu PETG HF** | профили заточены под этот филамент | — |

> **Почему именно Python 3.12.** CAD-стек (build123d поверх ядра OCCT) не имеет собранных
> колёс под 3.14 — установка на системном Python упадёт на сборке. `scripts/setup-agent.sh`
> поэтому явно просит у `uv` версию 3.12 и создаёт изолированный `.venv`.

> **Почему OrcaSlicer, а не Bambu Studio.** CLI Bambu Studio 02.05.00.66 падает с SIGSEGV
> в headless-режиме на macOS arm64 (upstream-баги #8569 / #3453 — разыменование null
> `wxTheApp`). OrcaSlicer — тот же самый CLI с теми же встроенными профилями BBL A1 / PETG HF,
> и он работает. `agent/slice.py` пробует Bambu Studio и **сам** уходит на OrcaSlicer при
> крэше — это ожидаемое поведение, чинить не надо.

## 2. Установка

```bash
# 1. Клонировать
git clone https://github.com/Ianromanenko/3d-print-agent.git
cd 3d-print-agent

# 2. Создать окружение (uv поставит Python 3.12 + CAD-стек)
bash scripts/setup-agent.sh
```

Скрипт ставит: `build123d` (CAD), `trimesh` + `manifold3d` (ворота печатаемости),
`pyvista` + `pillow` (offscreen-рендер для само-чека), `numpy`, `networkx`, `shapely`,
`python-dotenv`, `pytest`.

---

## 3. Проверка, что «руки» работают

Ещё до всякой настройки принтера прогони сквозной тест — он идёт целиком локально
(CAD → ворота печатаемости → слайсинг) и не требует ни принтера, ни Claude:

```bash
.venv/bin/python -m agent.pipeline gear --count 6
```

**Ожидаемый результат:** в `output/` появляется `.gcode.3mf` — и внутри него **6 раздельных
шестерён** на плите, а не один слипшийся объект. Это главный приёмочный критерий проекта.

Прогнать тесты:

```bash
.venv/bin/python -m pytest tests/agent -v
```

Если `gear` отработал — CAD, ворота и слайсер у тебя настроены правильно.

## 4. Настройка принтера (`.env`)

Пока этот шаг не сделан, агент всё равно умеет генерировать и нарезать — просто отдаёт
файл, который ты сам открываешь в Bambu Studio / Handy. Настройка нужна для автоотправки.

**4.1. На экране принтера** включи **LAN Mode** и **Developer Mode**. Там же посмотри
**Access Code** и **серийный номер**. IP принтера — в настройках сети.

**4.2. Создай `.env`** из шаблона:

```bash
cp .env.example .env
```

**4.3. Заполни три поля** своими значениями:

```bash
A1_IP=192.168.1.xx        # IP твоего принтера в локальной сети
A1_SERIAL=01Sxxxxxxxxxxxx # серийный номер с экрана принтера
A1_ACCESS_CODE=xxxxxxxx   # LAN access code (он же пароль для MQTT и FTPS)
```

Остальные поля не обязательны:
- `BAMBU_STUDIO_BIN` — только если слайсер лежит в нестандартном месте (иначе автодетект);
- `MESHY_API_KEY` — для генерации органики/фигурок, **эта стадия ещё не готова** (см. §6).

> `.env` в `.gitignore` — твои реквизиты никогда не попадут в git. Это осознанная схема:
> в репозитории лежит только `.env.example`-шаблон, все секреты читаются через переменные
> окружения в `agent/config.py`.

**4.4. Проверь связь:**

```bash
.venv/bin/python -m agent.pipeline ping
```

Команда специально написана так, что **никогда не падает** (всегда exit 0) — выключенный
принтер не должен блокировать генерацию и слайсинг.

## 5. Как пользоваться

**Основной режим — через Claude Code.** Запусти из папки проекта:

```bash
bin/print-agent "напечатай 6 шестерён Ø20мм, module 1, толщина 5, отверстие 5"
bin/print-agent --image ~/ref.jpg "как на фото, но 40мм"
```

Скрипт активирует venv и поднимает Claude Code-сессию, которая читает `agent/BRAIN.md` и ведёт
тебя по пайплайну. **Она обязательно остановится и переспросит**, правильно ли поняла, — и не
начнёт моделировать без твоего подтверждения. Это зашитое правило, а не случайность.

**Прямые команды (без «мозга»):**

```bash
.venv/bin/python -m agent.pipeline parse "6 шестерён Ø20"   # черновик спеки в JSON
.venv/bin/python -m agent.pipeline spec spec.json           # generate → gate → slice
.venv/bin/python -m agent.pipeline verify spec.json         # генерация + рендер + рубрика
.venv/bin/python -m agent.pipeline gear --count 6           # демо-путь
.venv/bin/python -m agent.pipeline ping                     # доступность принтера
.venv/bin/python -m agent.pipeline send out.gcode.3mf       # заливка на A1 + старт
```

**Опционально — быстрые триггеры:** `triggers/raycast/` (хоткей на Mac) и
`triggers/shortcuts/` (кнопка действия на iPhone через SSH). Настраиваются по README
внутри этих папок, для работы агента не обязательны.

## 6. Что готово, а что нет — честно

| Стадия | Статус |
|---|---|
| 1. Скелет пакета + окружение | ✅ |
| 2. Триггеры (Raycast / iPhone) | ✅ |
| 3. Понимание + блокирующее уточнение | ✅ |
| 4a. Генерация CAD (механика, эвольвентные шестерни) | ✅ |
| **4b. Генерация органики (Meshy)** | ❌ **не реализовано** |
| 5. Ворота печатаемости (watertight, split тел) | ✅ |
| 6. Само-чек ≥95% (рендер + рубрика) | ✅ |
| 7. Слайсинг с профилем PETG HF (ironing ON) | ✅ |
| 8. Связь с принтером (FTPS-заливка + MQTT-старт) | ⚠️ код готов, **на живом принтере не проверялся** |
| 9. Сквозной тест на живом A1 | ❌ не гонялся |

Практический вывод: **проси механику** (шестерни, кронштейны, размерные детали) — это код-CAD,
он детерминирован и протестирован. Фигурки и органику агент пока сделать не может и честно
об этом скажет. Стадия 8 написана и покрыта офлайн-тестами, но ты, возможно, станешь первым,
кто прогонит её против настоящего принтера — если поймаешь баг, напиши.

## 7. База знаний

`knowledge/` — то, на что агент опирается, принимая решения о печати. Читается и человеком:

- `01-bambu-a1-printer.md` — характеристики A1, подключение, ограничения
- `02-print-parameters.md` — таблица «симптом → причина → фикс»
- `03-ironing.md` — глажка верхних поверхностей
- `04-filaments.md` — сравнение пластиков
- `05-petg-hf-print-plan.md` — готовый профиль под PETG HF

`blueprint/` — архитектура, точные JSON-оверрайды слайсера, шпаргалка по управлению принтером.
`PLAN-3D-AGENT.md` — исходный план целиком, с обоснованием решений.

## Другое железо

Если у тебя **не** A1 с PETG HF:

- **Другой филамент, тот же A1** — правь `agent/profiles/PETG_HF_filament.json` и
  `PETG_HF_process.json` (температуры, обдув, ironing flow). Ориентир по значениям —
  `knowledge/05-petg-hf-print-plan.md` и `blueprint/petg-hf-slicer-profile.md`.
- **Другой принтер Bambu** — в `agent/config.py` жёстко прописан bundled-профиль машины
  `"Bambu Lab A1 0.4 nozzle"` (константа `BUNDLED_PROFILE_NAMES`). Замени на свой из числа
  тех, что идут в комплекте с OrcaSlicer. Проверь также рабочую зону: генератор
  раскладки исходит из 256×256×256 мм.
- **Не-Bambu принтер** — связь с принтером (`agent/printer.py`) завязана на протокол Bambu
  (MQTT + FTPS с access code), её придётся переписать. Остальной пайплайн
  (CAD → ворота → рендер → слайсинг) от вендора не зависит.

## Если что-то не работает

| Симптом | Причина и что делать |
|---|---|
| `uv not found` | `brew install uv` |
| Падает установка build123d / OCCT | Взялся системный Python 3.14. Удали `.venv` и перезапусти `scripts/setup-agent.sh` — он пинит 3.12 |
| `No slicer CLI found` | Поставь OrcaSlicer: `brew install --cask orcaslicer` |
| Слайсинг падает с SIGSEGV | Это баг CLI Bambu Studio, ожидаемо. Убедись, что OrcaSlicer установлен — фолбэк сработает сам |
| `ping` молчит / принтер не виден | Проверь LAN Mode + Developer Mode на экране принтера, и что Mac и A1 в одной сети (A1 — **только 2.4 ГГц**) |
| Агент не задаёт уточняющих вопросов | Ты запустил `pipeline` напрямую, минуя «мозг». Диалог — только через `bin/print-agent` в Claude Code |
